# S-012 スマホでの図の見せ方：3つの案（ユーザーが選ぶ）

今の図（スマホ 390px）：[s012_now.png](s012_now.png)。困りごとは、空白が多い・丸が小さい・操作しにくい・拡大しないと名前が出ない・カードが図を隠す。
**どれにするかはユーザーが決める。決まるまで図の大きな形は変えない。** 見本はどれも本物のデータ（tech_network_graph.js）で動き、押すと選び直せる。

## よい所・気になる所

- **A**：今の図と同じ形（パソコンと同じ）なので覚え直さなくてよい。つながりは線で見える。ただし混んだ所（1950〜70年の半導体）では名前が出ない丸が残り、全体を見渡すにはピンチ（2本の指で縮める）が要る
- **B**：いちばん押しやすく、文字も大きい。「何が要ったか・何ができたか」がすぐ分かる。ただし全体の広がり（地図らしさ）はスマホでは見えなくなる
- **C**：スクロールだけで全部見られ、空白がない。時代の流れが分かる。ただしつながりは線ではなく色なので、遠い時代の前提は画面の外になる（カードの数で分かる）

組み合わせもできる（例：B を基本にして「全体の地図」で A）。

## 参考（ほかの所がスマホでどう見せているか）

- 地図アプリの下の引き出し：Material Design（Google のデザインの決まり）は、引き出しを出したまま地図を動かせる形を例に挙げる「A persistent bottom sheet enables place details to remain on-screen while a map is panned around」 https://m1.material.io/components/bottom-sheets.html → 案A
- Obsidian（メモのアプリ）の「ローカルグラフ」：今のノートにつながる物だけを出し、深さ（何段先まで）をスライダーで選ぶ https://obsidian.md/help/plugins/graph → 案B
- スマホでグラフを描く研究（JGAA 2012）：小さな画面では「全体を先に見せる」が難しいので、1つを中心にとなりへ進む見せ方を提案 https://jgaa.info/index.php/jgaa/article/view/paper252 → 案B
- Chunky Chains（2026 の論文）：スマホは縦のスクロールが基本なので、幅を決めて図を縦に積む描き方 https://arxiv.org/abs/2607.06029 → 案C
- GraphTiles（NCSU 2013）：つながりを線でなく、アイコンのマスを「何歩離れているか」の列に並べる。スマホの IMDb より早く情報を見つけられたという評価 https://techrep.csc.ncsu.edu/2013/TR-2013-6.pdf ⚠️（このサイトは証明書が切れていて中を開けなかった。内容は検索結果の要約による） → 案C
