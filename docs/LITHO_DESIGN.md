v0.3 の中心。チップ・マスク・層のデータの形と、機械どうしのつなぎ方を決める（O-002、2026-10-20、担当 A＝IMP）。

C（IMP2）と E（IMP4）の機械は、ここに書いた**データの形と関数だけ**を使う（中を直接いじらない）。形を変えるときは A がこのファイルを先に直す。

## 1. 全体の流れ（本物 → ゲーム）

本物のプレーナ工程（1959 ヘルニ／ノイス）は「膜を作る → 写真で模様を写す → 削る／しみ込ませる」をマスクの枚数だけくり返す。

```
 製図台で方眼に描く ─→ 設計図（layout_sheet：全部の層）
        │ 層ごとに切り出す
        ▼
 原図（rubylith：1つの層）─[7-11] 縮小カメラ＋乳剤─→ フォトマスク（photomask）
                                                       │
 シリコンの板 ─[9-15]酸化─→ ┌──────────────── 1枚のマスクごとにくり返す ───────────────┐
                            │ [9-19] レジスト塗布 → [9-20] 露光（マスク＋光）→ [9-21] 現像 │
                            │ → [9-06] 酸化膜を削る（HF）→ レジストをはがす               │
                            │ → [9-16] 拡散（窓から B か P）／ [9-25] Al を付けて削る      │
                            └──────────────────────────────────────────────┘
        ▼
 加工中のウェハー（chip_state：何をどこまでしたか）─→ 検査台（プローブ）で判定・電流を見る
```

- **1枚のウェハー＝同じチップがたくさん並んだもの**（本物のステップ・アンド・リピート）。ゲームではウェハー1枚に「チップ1つ分の中身」を持たせ、それが並んでいることにする（省略：チップごとのばらつき・欠陥は v0.5 の歩留まりで）
- 方眼の1マス＝その露光の方法で描ける**いちばん小さい形**（最小線幅）

## 2. 層（LayerKind）

| 層 | 意味（本物） | 描いた所 | 工程（ノード） | v0.3 |
|---|---|---|---|---|
| `DIFF_N` | n型の拡散（リンをしみ込ませる） | 窓を開けて n型にする所 | [9-06] 窓開け → [9-16] 拡散 | ✅ |
| `DIFF_P` | p型の拡散（ホウ素） | 窓を開けて p型にする所 | 同上 | ✅ |
| `CONTACT` | 金属と半導体をつなぐ窓 | 金属がシリコンにさわる所 | [9-06] 窓開け（このあと Al） | ✅ |
| `METAL` | アルミの配線 | 金属を残す所 | [9-25] Al を付ける → 削る | ✅（1層） |
| `GATE` | MOS のうすい酸化膜（ゲート） | — | [9-23] | 後（v0.4） |
| `METAL2`・`VIA` | 2層目の配線と、その間の窓 | — | — | 後 |

- **プレイヤーは「その物がある所」を描く**。ポジ型レジスト（光が当たった所が溶ける）なので、本物のマスクは層によって白黒が逆になる（窓の層は透明＝描いた所、金属の層は不透明＝描いた所）。この向きの違いは関数の中で自動で扱う（へえ：マスクは「写真のネガ」と同じ）
- **拡散は順番が大事**：あとからしみ込ませた方が濃いので、同じマスに n と p を重ねると**あとの方の型**になる（本物の「打ち返し」＝counter-doping）。設計図の層は「工程の順」に並べる
- v0.3 の拡散は**最大3回**＋アルミ配線1層（**決定 INBOX S-001**：方針6の「1〜2層」は金属の層の数。2層目の金属はのちの技術）。1960年ごろのフェアチャイルドのプレーナ IC と同じ「分離・ベース・エミッタ」の3回（REFERENCES L1）
  - 本物はエピタキシー［9-30］で n の層を育ててから p の分離の壁をしみ込ませる。v0.3 はエピタキシーがないので、p型の板に n の島をしみ込ませる三重拡散で代わりにする（データの形は同じ：板を 'n' にして p の壁を描けば本物の形になる）

## 3. 方眼の大きさ（露光の方法 → 描ける広さ）

本物の解像度 CD = k1 × λ / NA（DESIGN「目玉：露光装置」）。CD が小さいほど同じ面積にたくさん描ける。
ゲームでは「1マス＝その方法の CD」とし、チップの大きさは同じにして、**方眼の1辺のマス数 N を CD から決める**。

  **N = 8 × (10 µm ÷ CD)^(1/3)** を 4 の倍数に丸める（最初の密着露光の CD を約 10 µm とした）

| 露光の方法（ノード） | 光 | 本物の CD のめやす | N（1辺） |
|---|---|---|---|
| 密着露光（[9-20]、1960ごろ） | 水銀 g線 436 nm | 約 10 µm | **8** |
| 投影の等倍露光（1973 ⚠️） | 水銀の線 | 約 3 µm | 12 |
| g線ステッパー（[9-39]、1978） | g線 436 nm | 約 1 µm | 16 |
| i線ステッパー（[9-39]） | i線 365 nm | 約 0.35 µm | 24 |
| KrF エキシマ（[7-20]） | 248 nm | 約 0.13 µm | 36 |
| ArF エキシマ（[7-20]） | 193 nm | 約 65 nm | 44 |
| ArF 液浸（[7-16]） | 193 nm（水の中） | 約 38 nm | 52 |
| EUV（[9-40]） | 13.5 nm | 約 13 nm | 72 |

- 省略（ガイドに書く）：本物は CD が 1/10 になるとトランジスタの数は 100 倍（面積の2乗）。ゲームは3乗根にちぢめた（N² で約 4.6 倍）。理由：画面に入る・遊べる大きさにするため。数字の比べ方は「CD の比」でガイドに本物の値を出す
- 細かい方法で作ったマスクを粗い方法で焼くと**ぼける**（N が大きすぎるマスクは焼けない：`expose` が `too_fine` で断る）。粗いマスクを細かい方法で焼くのはよい
- CD の値（とくに 1973 の投影の等倍露光）は REFERENCES に出典を足してから確定 ⚠️

## 4. データの形（データコンポーネント）

どれも `ModDataComponents` に登録する（A）。Codec は `RecordCodecBuilder`、通信は `ByteBufCodecs.fromCodec...`（A が javap で確かめて API_26X に書く）。

### 4.1 `BitGrid`（方眼1枚）
```java
record BitGrid(int size, List<Long> bits)   // size×size マス。マス (x, y) は bits の (y*size + x) ビット目
  boolean get(int x, int y); BitGrid with(int x, int y, boolean on); int count(); boolean isEmpty();
  static BitGrid empty(int size);
```
- size は 4〜72。72×72＝5184 ビット＝long 81 個

### 4.2 設計図 `semiconductor-lab:chip_design`（アイテム layout_sheet＝方眼紙に描いた設計）
```java
record ChipDesign(int size, String name, List<DesignLayer> layers)
record DesignLayer(LayerKind kind, BitGrid cells)      // 並び＝工程の順
```
- 製図台（A）で描く。元に戻す（undo）・やり直しは画面の中だけ（保存は確定したときだけ）
- name はプレイヤーが付ける（なくてよい）

### 4.3 マスク `semiconductor-lab:mask`（アイテム rubylith＝原図、photomask＝フォトマスク）
```java
record MaskData(int size, LayerKind kind, BitGrid cells, String design, int index, int artworkMm, int reduction)
//   design・index：どの設計図の何枚目か（表示用。同じ設計図のマスクをそろえて使うと「合っている」）
//   artworkMm・reduction：原図の1辺（mm）と縮小率（S-001。今は 0・1＝原図なしの近似。[7-11] の縮小カメラが入れる）
//   5つの引数のコンストラクタは artworkMm=0・reduction=1
```
- 原図 → フォトマスクは [7-11]（縮小カメラ）が MaskData をそのまま写す。フォトマスクだけが露光に使える
- 密着露光ではマスクが傷む（本物）：photomask はアイテムの耐久（damage）で回数を数える。何回で壊れるかは [9-20] の担当が決める

### 4.4 加工中のウェハー `semiconductor-lab:chip_state`（アイテム process_wafer）
```java
record ChipState(
    int size,                 // 0 ＝ まだ露光していない（最初の露光で決まる）
    char substrate,           // 'p' か 'n'（もとの板のドーパント。Dopant から）
    List<Applied> done,       // 終わった層（工程の順）。Applied(LayerKind kind, BitGrid cells)
    BitGrid windows,          // いま酸化膜に開いている窓（なければ empty）
    Resist resist,            // NONE / COATED / EXPOSED / DEVELOPED
    BitGrid resistPattern,    // EXPOSED：光が当たった所、DEVELOPED：レジストが残っている所
    boolean metalFilm,        // Al を一面に付けて、まだ削っていない
    int reclaims,             // 研磨してやり直した回数（§5 reclaim）
    int contamination         // 汚れ（[9-14]、E と決めた）：削る・はがす・拡散・Al のたびに +1、clean で落とす。失敗にはしない
)
```
- 酸化膜つきの板（oxidized_wafer、[9-15]）にレジストを塗った時点で process_wafer に変わる（純度・ドーパント・膜の厚さは受け継ぐ）
- ツールチップ：「工程：n拡散 → p拡散 → （いま）レジスト露光ずみ」の1行と、終わった層の数

## 5. 工程の関数（`litho/ChipOps`）— C・E の機械はこれを呼ぶ

どれも `static Result op(ItemStack wafer, …)`。成功なら wafer の chip_state を書き換えて `Result.ok()`、
だめなら何も変えずに `Result.fail("理由のキー")`（機械の画面に lang `litho.semiconductor-lab.fail.<理由>` を出す）。
**材料をほとんど失わない**：失敗は「その工程をやらない」だけ。ウェハーは消えない。

| 関数 | 呼ぶ機械（ノード・担当の予定） | できる条件 | すること | 失敗の理由 |
|---|---|---|---|---|
| `coat(w)` | レジスト塗布 [9-19]（C） | resist＝NONE、酸化膜か Al 膜がある | resist＝COATED | `not_oxidized`・`already_coated` |
| `expose(w, mask, tool)` | 露光 [9-20]／[9-39]（C か E） | COATED、mask の size ≤ tool の N、size が前の層と同じ | resist＝EXPOSED、resistPattern＝光の当たる所（層の向きを自動で） | `no_resist`・`too_fine`・`size_mismatch` |
| `develop(w)` | 現像 [9-21]（C） | EXPOSED | resist＝DEVELOPED（ポジ型：光の当たった所が溶ける） | `not_exposed` |
| `etchOxide(w)` | 酸化膜エッチング [9-06]（E：HF） | DEVELOPED、Al 膜なし | windows＝レジストのない所 | `not_developed` |
| `etchMetal(w)` | Al のエッチング [9-25]（担当未定） | DEVELOPED、Al 膜あり | done に METAL、metalFilm＝false | `no_metal` |
| `strip(w)` | レジストはがし（どの機械でも） | resist≠NONE | resist＝NONE（**やり直し**：露光をまちがえても、はがして塗り直せる＝本物のリワーク） | — |
| `diffuse(w, type)` | 拡散炉 [9-16]（A が窓ありに直す） | 窓が開いている、resist＝NONE | done に DIFF_N/P（窓の形）、窓は閉じる（拡散中に酸化膜が育つ） | `no_window`・`resist_on`・`too_many` |
| `depositMetal(w)` | Al 蒸着 [9-25]（担当未定） | resist＝NONE | 窓があれば done に CONTACT（窓の形）、metalFilm＝true | `resist_on` |
| `clean(w, target)` | 洗浄槽 [9-14]（E） | resist＝NONE、汚れ ＞ target | 汚れを target まで落とす（段階1＝0。RCA との差は v0.5 の歩留まりで） | `resist_on`・`no_dirt` |
| `reoxidize(w)` | 酸化炉 [9-15]（E、すでにある） | resist＝NONE | 窓を閉じる（窓の開けまちがいのやり直し） | — |
| `reclaim(w)` | 研磨 [9-13]（担当未定） | — | 全部の層を消して酸化膜つきの板に戻す（2回まで。本物の再生ウェハー） | `too_many_reclaims` |

- 機械に入れてよい物の判定：`ChipOps.canCoat(w)` など、同じ名前の `can…` を用意する（MachineLayout の入口の条件に使う）
- 拡散の順：v0.3 は `diffuse` を3回まで（`too_many`）
- 合わせ（アライメント [8-17]）のずれは v0.3 ではなし。後でずれを足すときも、関数の形は変えない

## 6. 判定（検査台・プローブ）と回路の計算

### 6.1 チップの中身を組み立てる：`ChipModel.of(state)` / `ChipModel.of(design)`
- マスごとの型（substrate → 拡散を順に上書き）、CONTACT、METAL を重ねた**完成した姿**
- `of(design)` は「全部うまくいったら」の予想。製図台の**予想図と断面図**はこれを描く（正解の名前は出さない）

### 6.2 回路を取り出す：`Netlist.extract(model)`
1. **領域**：同じ型でつながったマス（上下左右）。いちばん外の型が板（substrate）
2. **接合**：型のちがう領域が接している所＝pn 接合（ダイオード）
3. **配線**：METAL のつながり＝1本の線（net）。CONTACT のマスで、下の領域とつながる
4. **パッド**：チップのふち（外周のマス）にかかった配線＝外とつなぐ所（本物のボンディングパッド）
5. **部品**：
   - 抵抗：1つの領域に別々の線が2本つながり、まわりと接合で分かれている。値＝面抵抗（Ω/□）×（長さ÷幅＝マスの数）。面抵抗：n の島 1 kΩ/□、p 200 Ω/□、n+ 10 Ω/□（1960年代のバイポーラ IC の典型値、REFERENCES L3 で確定。板の 5 kΩ/□ だけゲームの値 ⚠️）
   - ダイオード：p の領域と n の領域が接し、それぞれ別の線につながる
   - トランジスタ（npn）：n の中の p の中の n（入れ子）、3つとも別の線につながる（エミッタ・ベース・コレクタ）。pnp は逆
6. **計算**（`Circuit.solve(netlist, パッドの電圧)`）：抵抗・ダイオード（ショックレーの式）・トランジスタ（エバース・モルの簡単な式）の直流の回路を解く → 各パッドの電流、各部品の電流。検査台はこれで「電流の流れ方」を矢印と太さで見せる
7. **論理**（`Circuit.logic(netlist, 入力)`）：電源 5 V・0 V と入力（0 V／5 V）を与えて出力が 2.5 V より上か下か。のちに電卓・コンピュータのチップがこれで「本当に計算」する（方針5）

### 6.3 発見：`Discoveries.match(netlist)`
- 発見の一覧（`litho/Discovery`：id・年・ノード・判定）。上から順に、v0.3 は4つ：

| id | 名前 | 年 | ノード | 判定 |
|---|---|---|---|---|
| `diffused_resistor` | 拡散抵抗 | 1958 | [9-22] | 抵抗が1つ以上 |
| `junction_diode` | pn 接合ダイオード | 1940 | [9-05] 系 | ダイオードが1つ以上 |
| `planar_transistor` | プレーナトランジスタ | 1959 | [9-18] | トランジスタが1つ以上 |
| `rtl_not` | NOT（RTL のインバータ） | 1961 ⚠️ | [10-09]・[10-10] | トランジスタ1＋抵抗（コレクタ側）で、計算すると入力 0→出力 1、1→0 |

- 一致したら「あなたは 1959 年のプレーナトランジスタを自分で作った」と知らせ、図鑑（zukan）と進捗を開く（③、A）
- 年と出典は REFERENCES に1項目ずつ（A）。⚠️ のものは確かめてから
- 判定は「形」ではなく**つながり方**で見る（同じ回路なら、どこに描いても・どの向きでも同じ発見）

### 6.4 v0.3 の大きさで NOT が入るか（8×8 の例 = `LithoExamples.notGate()`）
p型の板。n の島（コレクタ）5×5 の中に p（ベース）3×3、その真ん中に n（エミッタ）1マス。島の右と下に n の細い帯（コレクタの抵抗・ベースの抵抗。本物のマイクロロジックと同じくベースにも抵抗）。配線はその上の Al で、ふちの4か所がパッド（0 V・電源・入力・出力）。
→ **拡散3回（n・p・n）＋窓＋金属1層**で入る。拡散2回だと、トランジスタと抵抗を同じ板の上で分ける島が作れない（§2 の ⚠️ 未決）
- 計算の結果（GameTest litho_core）：入力 0 V → 出力 5.0 V、入力 5 V → 出力 約 1.1 V。低い方が 0.2 V まで下がらないのは、島（コレクタ）の抵抗が大きいから（埋め込み層のない最初のころの IC と同じ。のちの [9-30] エピタキシーと埋め込み層で下がる）
- 判定のきまり：トランジスタのベースは拡散した領域（板そのものはベースにしない）

## 7. 画面（A）

- **製図台**（drafting_table）：**材料なしで描ける**（⚠️ 近似、INBOX S-001。本物は大きな原図＝ルビリスを切って写真で縮小。lang の placeholder とここに明記し、[7-11] とつなぐときに MaskData の artworkMm・reduction を使う）。方眼に描く（左クリック＝塗る、右クリック＝消す、層の切りかえ、元に戻す・やり直し）、**予想図**（上から見た完成の色）、**断面図**（1行を選ぶと横から見た図：p＝赤・n＝青・酸化膜＝白・金属＝灰）。確定すると layout_sheet に保存。層ごとに原図（rubylith）を取り出す
- **検査台**（probe_station）：process_wafer を置く。パッドごとに 0 V／5 V／つながない を選ぶ → 電流の矢印・各部品の名前（**発見したあとだけ名前が出る**。まだなら「？」）
- 画面の文字は MachineLayout のデータ、IMP-30 の検査（gui_layout）を通す。方眼の大きさが変わるので、方眼は「マスの大きさ × N」が画面の枠に入るように（8×8＝1マス 8px、16×16＝4px、それより大きいときは拡大・移動）

## 8. C・E がつなぐ所（まとめ）

| 誰が | 何を作る | 使うもの |
|---|---|---|
| C（IMP2、INBOX O-003） | photomask の登録と [7-11] 銀塩マスク（縮小カメラ：rubylith の mask 成分をそのまま photomask に写す）・のちのクロムマスク、露光の光学（光源・投影レンズのノード、ExposureTool の λ・CD・N の出典、ガイドの「アッベの限界」）。[9-19] レジスト塗布・[9-21] 現像は C の INBOX で割り当てが来たら | `ChipOps.coat`・`develop`・`strip`・`expose`、MaskData（成分 `semiconductor-lab:mask`）、photomask の耐久 |
