\## 化学ルール ✅（2026-10-19 決定）
1. バニラの元素は使ってよい。ただし反応は本物どおり（石炭=C、骨粉=Ca3(PO4)2、砂=SiO2、硫黄ブロック=天然硫黄 など）
2. バニラにない元素は、本物の産出源を新しい鉱石として追加する。別の物で代用しない
3. 省略するのは「工程の細部（温度・触媒・段数）」だけ。「化学の筋道」は省略しない。省略箇所はガイドブックに明記
4. 全レシピに本物の反応式をつけて docs/CHEMISTRY.md で管理
5. 新しいバニラ要素をレシピに使う前に、ゲーム内で名前とIDを確認する

## 第1章 化学フロー（v0.1 改訂版）✅
- Ge入手A：閃亜鉛鉱（新鉱石・ワールド生成をv0.1に前倒し）→ 精錬 → 亜鉛 + Ge精鉱 + インジウム(少量)
  - v0.1は仮実装：かまど（→亜鉛）＋作業台で砕く（→Ge精鉱・インジウム少量）。第2章の機械共通化で専用の精錬炉に置換
- Ge入手B：石炭 →かまど→ 石炭灰 → Ge精鉱（産地限定の省略を明記）
- 硫黄：バニラは全てブロック（硫黄 sulfur／強力な硫黄 potent_sulfur／尖った硫黄 sulfur_spike）。「硫黄の破片」は存在しない。MODで「硫黄の粉」を追加：尖った硫黄1→粉2、硫黄ブロック1→粉4。尖った硫黄は硫黄の洞窟で素手でも回収可、行商人も販売。硫黄は可燃・爆発物（本物も火薬の成分）とガイドブックに明記
- 硫酸：硫黄の粉 →かまど（燃焼）→ 二酸化硫黄 SO2 →＋水バケツ→ 硫酸（接触法。SO2→SO3 の酸化・触媒V2O5 を省略と明記。専用機械ができたら3段に）
- 抽出：Ge精鉱 + 硫酸 → 二酸化ゲルマニウム GeO2 ／ GeO2 + 木炭 → 還元ゲルマニウム（未精製）（工業は水素還元と注記。純度の数字は精製炉の段階でのみ表示）
- 精製：帯域精製炉 98% → 6N → 9N（本物の GeCl4 蒸留の分を精製炉が担う、と明記）
- n型ドーパント：骨粉 + 砂 + 木炭 → リン（ヴェーラー法 Ca3(PO4)2 + SiO2 + C → P4。本物は約1500℃電気炉、温度は省略）
- p型ドーパント：インジウム（閃亜鉛鉱の副産物）
- ドーピング：帯域精製炉でゾーンレベリング（Pfann）。9N以上のGe（最大8）＋ドーパント1 → n型/p型Ge。作業台の固体混合は廃止
- 点接触型トランジスタ(1947)：n型Ge + 金塊2（針）+ 銅（ベース電極）
- 合金接合型トランジスタ(1952, PNP)：作業台で [In][n型Ge][In] → かまどで加熱（合金化）
- 成長接合型(1951, NPN)：第1章では解説のみ。第2章のCZ引き上げ機で実装
- トランジスタラジオ：合金接合型 ×3 ＋ 黒鉛（炭素抵抗）＋ 銅ケーブル（コイル）＋ ライデン瓶（コンデンサ ⚠️）＋ 磁石（スピーカー）＋ 亜鉛インゴット・黒鉛棒（乾電池 ⚠️）。2026-10-20 にレッドストーンを外した
- 廃止：「石炭灰+水バケツ→粗Ge」「精製Ge+金+銅→トランジスタ」「粗Ge→精製Ge 仮レシピ」

## v0.2a 電気 設計 ✅（2026-10-19 決定）
- 単位：J（蓄積）/ W（消費）。1 W = 0.05 J/tick。本物の桁を使う（精製炉 数kW、アチsoン炉 MW級、EUV 約1MW）
- 電圧：データ欄（voltage）を用意。変圧器・高電圧は v0.4〜。電線損失は v0.2a は簡易（距離%）、式 I²R はガイドへ
- 他MOD互換：内部は J/W、共通エネルギーAPIへの換算ブリッジは後で
- 鎖：石炭→ボイラー→蒸気機関/タービン→発電機→電気。水車も（歴史順：水車→蒸気機関→タービン）
- 発電機：永久磁石式（磁鉄鉱）→ 自励式（1866 ジーメンス、鉄心のみ）のアップグレード
- 電解槽：水→H2+O2（黒鉛電極）。H2 で GeO2・WO3 を水素還元。木炭還元も残す（歴史的・小規模）
- 真空ポンプ→真空管（タングステンフィラメント）→高周波発振器 ＝ 仮①を置換
- アチソン炉（炭素+砂、大電力）→人造黒鉛→高純度ボート ＝ 仮②を置換
- 鉛蓄電池（方鉛鉱→鉛、硫酸）は v0.2a 後半 or v0.2b
- 容器：H2/O2 はボンベ（容器システムの第一歩）

## v0.4 電気の土台：交流・電圧・変圧器（O-012 設計、A）— ✅ **決定（S-007、2026-10-20、ユーザー「おすすめで」）：Q12-1 案A 網ごと・Q12-2 案A 交流／直流の印だけ・Q12-3 案A 電圧の段で損失を割る**

### 今（v0.2a〜v0.3）の電気
- 単位は J（貯める）と W（使う）。1 W = 0.05 J/tick。ケーブルの網（energy/CableNetwork）は「1本の導体」：発電 → 機械 ＞ 電池の放電 ＞ 電池の充電、網あたり 1 MW まで、損失は「いちばん長い経路の本数 × 1%」
- 電圧の欄はある（EnergyStorage.getVoltage、SimpleEnergyStorage の voltage）が、どこも使っていない。交流と直流の区別はない
- 本物とのずれ（今は近似⚠️）：水車・蒸気機関の発電機は自励式ダイナモ＝**直流**。アーク炉 [3-15] は本物は交流のことが多いが直流で近似（2026-10-20 決定）

### 本物のしくみ（ガイドと note に書く中身）
- 電力 P = 電圧 V × 電流 I。電線で失う電力は I²R（電流の2乗 × 電線の抵抗）。同じ電力を送るなら、電圧を10倍にすると電流は 1/10、損失は 1/100
- 電圧を変えられるのは**交流**だけ（変圧器は、変化する磁束でとなりのコイルに電圧を生む。直流では磁束が変わらない）。巻き数の比＝電圧の比（理想なら電力は同じ、本物は 98〜99%）
- **直流が要る物**：電気分解（電解槽・クロルアルカリ・アルミの精錬）、めっき、真空管の陽極、のちのイオン注入の高電圧。だから交流で送って、使う所で整流器 [4-11] で直流に直す
- 年：交流発電機（オルタネーター）は 1880年代（フェランティ 1882 など⚠️）、閉じた鉄心の変圧器 ZBD 1885 [4-10]、多相交流と誘導モーター（テスラ 1888）、電力用の整流器はクーパー・ヒューイットの水銀整流器 1902 [4-11]（真空管の二極管 1904 より前）

### 決めること（大きな選択：LOG に案、ユーザーに聞く）
- **Q12-1 電圧をどこに持たせるか**
  - 案A：**網ごと**に1つの電圧（低圧 LV／高圧 HV など数段）。ケーブルの種類で決まり、変圧器が2つの網をつなぐ。機械は「受けられる電圧」を持ち、違う網につなぐと動かない（理由を表示）
  - 案B：**機械ごと**：網は電圧を持たず、機械がそれぞれ受け口に「必要な電圧」を持つ。変圧器は機械の前に置く変換ブロック
  - 案C：電圧は**ケーブルの格だけ**（高圧の電線は損失が小さく、上限が大きい）。機械はどの網からでも受ける
- **Q12-2 交流をどこまで扱うか**
  - 案A：網に「交流／直流」の印だけ（周波数は扱わない）。変圧器は交流の網だけ、電解槽などは直流の網だけ、整流器が交流 → 直流
  - 案B：周波数（50／60 Hz）まで扱い、発電機どうしの同期（周波数を合わせないとつなげない）も遊びにする
  - 案C：交流・直流は区別しない（全部これまでどおり）。変圧器は「損失を減らす電圧の段」の道具だけ
- **Q12-3 損失の式**
  - 案A：今の「最長経路 × 1%」を電圧の段で割る（高圧ほど小さい：電圧が10倍なら 1/100）。計算は軽い
  - 案B：ケーブル1本ごとの抵抗で I²R を本当に計算（経路ごと）。正確だが、網が大きいと重い

### 今の機械との互換（どの案でも守る）
- 今ある網・機械・電池は、そのまま「低圧の直流」の網として動く（今のワールドがこわれない）。電圧の欄の初期値も低圧
- 発電機の自励式ダイナモ＝直流（本物どおり）。交流は新しいブロック「交流発電機」から（TECH_TREE に新しいノードを足す。前提は [4-05]・[4-03] など、年は出典で確かめる）
- 直流が要る機械（電解槽・塩水の電解・のちの高電圧）は、交流の網には直接つながらない（案A のとき）。整流器 [4-11] を通す
- [4-11] の前提は本物の年どおり：水銀整流器（1902、[1-45] 水銀 ✅・[5-11] 真空容器 ✅）を入れ、[5-02] 真空管（1904）は「or」の別の道にする（network_proposals Y-2）
- GameTest：今の網のテスト（cable_network など）が全部そのまま通ること。新しい網は別のテストで

### 実装の計画（S-007、A）
- **電流の種類** energy/Current（DC・AC・ANY）と **電圧の段**（0＝低圧 約200V、1＝高圧 約2000V＝10倍 ⚠️ゲームの値）を EnergyStorage に（既定：ANY・低圧＝今の機械・網は全部そのまま）
- **網の電圧**：ケーブルの種類で決まる。銅ケーブル＝低圧（今のまま、1本 1%）、新しい高圧の電線＝高圧（1本 0.01%＝1/100、通過上限 10MW）。種類のちがうケーブルどうしはつながらない。網は自分と同じ段の受け口だけを集める（機械・発電機は低圧なので、高圧の電線には変圧器しかつながらない）
- **網の交流／直流**：発電機と電池で決まる。全部が交流なら交流の網、直流（今のダイナモ・電池・太陽電池）なら直流の網。交流と直流が混ざった網は配らない（ケーブルを右クリックで「交流と直流が混ざっている」）
- **機械**：ふつうの機械はどちらでも動く（電熱・モーター）。直流しか使えない機械（電解槽＝電気分解・塩水の電解、鉛蓄電池の充電）は交流の網からはもらえない → 整流器を通す
- **新しいブロック・アイテム**：
  - 交流発電機（アイテム、自励式ダイナモと同じく発電機に持って右クリックで積み替え）：その発電機が交流を出す（出力は自励式と同じ2倍）。年は 1880年代（出典で確かめる⚠️）、新しいノード
  - 変圧器 [4-10]（1885 ZBD）：後ろの面＝入力、前の面＝出力。それぞれの面の電圧の段は、その面に付いたケーブルの段（低圧→高圧＝昇圧、高圧→低圧＝降圧）。交流の網でしか働かない（直流では磁束が変わらない）。効率 98%
  - 高圧の電線（[4-10] の続き、1886 スタンレーのグレート・バリントン ⚠️）
  - 整流器 [4-11]（1902 クーパー・ヒューイットの水銀整流器）：後ろ＝交流の入力、前＝直流の出力（同じ段）。効率 95% ⚠️
- **遊び方の1行**（TECH_TREE・ガイドに）：①高い電圧で送る＝同じ電線でも損失が 1/100 になり、遠くの発電所から送れる ②交流にする＝変圧器が使えるのは交流だけ ③整流器が要る＝電気分解などは直流でしか動かない
- 確認：今の GameTest（網・電池・発電機）は全部そのまま通る。新しい GameTest：高圧の損失・変圧器（交流だけ）・整流器・直流の機械は交流から動かない

## 作り方の3段 ✅（2026-10-20 決定）
1. **工程は機械の中で**：化学反応・加熱・精製・結晶成長などは機械のブロックの中で行い、温度・圧力・時間（と電力）を GUI で見せる（今のアーク炉・シーメンス炉・CZ 引き上げ機・拡散炉と同じ）

- 作業台に残すのは、手で作れる物と簡単な組み合わせだけ（れんがの成形、道具、ケーブルなど）
- 組立台とマルチブロックの仕組みは、v0.2b の区切りの「機械の共通化」と一緒に設計する（ROADMAP）。それまでは今の作業台レシピのまま（トランジスタラジオなど）

## 機械の共通化 ✅（2026-10-20 IMP-28）

## 露光とマスク（v0.3 の中心）📝 ユーザーの決定（2026-10-20、INBOX O-002）→ 仕様は docs/LITHO_DESIGN.md

## 容器のしくみ ✅ 判断と設計（2026-10-20 IMP-28）→ 実装 IMP-33（2026-10-20。魔法瓶は [5-09] と一緒に、フッ酸は [2-10] と一緒に）
**判断：要る。ただし「なんでも入るタンク（液体の仕組み）」は作らない。「本物の容器＝本物のアイテム」と「中身入りのアイテムは、入っている容器を1つ決めておく」だけにする。**
- 要る理由（化学ルール1。CHEMISTRY「容器」の節に「今は容器なしで素手持ち。要修正」と書いてある）
  1. **白リン**（phosphorus）：空気中で約30℃で自然発火するのに、今は素手で持っている（本物は水の中に保管。note2 に書いただけ）
  2. **酸**（硫酸・塩酸）：「ガラス瓶入り」のつもりだが、瓶がどこからも来ず、使っても戻らない（ガラスが湧いて消える）
  3. **二酸化硫黄**：気体なのに袋もボンベもない（ほかの気体は「袋詰め」＝CHEMISTRY #33）。**水銀**：「容器入り」と言うだけで容器がない
  4. **v0.3 で本当に困る**：IC の工程は [2-10] フッ酸（SiO2 を溶かす＝**ガラス瓶に入れられない**。本物は昔は鉛・ろう・ガタパーチャの瓶、今はポリエチレン）・過酸化水素・現像液・液体窒素（[5-09]、魔法瓶＝デュワー瓶）・シランなどの危ないガス（ボンベ）を使う。「何に入れるか」がそのまま化学の学び
- 要らない理由（＝作らないもの）：液体を管で流す・タンクに mL でためる仕組み（Fabric の液体の API）は重く、今の機械（電解槽・塩酸合成炉…）はバケツ・袋・ボンベで足りている
- **しくみ**
  - **容器の種類**（machine/Vessel の一覧。どれも本物のアイテムで、ノードの前提に入る）：

    | 容器 | 中身の例 | アイテム | 前提 |
    |---|---|---|---|
    | 袋（ゴム引き布） | 水素・酸素・塩素・窒素・アルゴン・**二酸化硫黄** | 今の「袋詰め」のまま（袋はレシピに出さない、#33） | ✅ |
    | 鋼のボンベ | 同じ気体の高圧（50mol） | empty_gas_cylinder（今ある） | [6-03] ✅ |
    | ガラス瓶 | 硫酸・塩酸・過酸化水素 | glass_bottle（新：ソーダ石灰ガラスで作る） | [2-14] ✅ |
    | 水の入ったガラス瓶 | 白リン | 同じ glass_bottle＋水 | [2-14] ✅ |
    | 鉄のフラスコ | 水銀（本物は 76 ポンド＝約 34.5kg 入りの鉄の瓶が取引の単位） | iron_flask（新） | 鉄 ✅ |
    | 鉛の瓶 → ポリエチレンの瓶 | フッ酸 | lead_bottle（新、[1-27] 鉛 ✅）→ のちに [2-37] ポリエチレン | [1-27] ✅ |
    | 魔法瓶（デュワー瓶） | 液体窒素 | dewar（新） | [5-09] ❓（そのノードと一緒に） |
  - **中身入りのアイテム**は登録のときに容器を1つ書く：`Reg.contained("sulfuric_acid", Vessel.GLASS_BOTTLE)`。これで①作業台で使うと空の容器が戻る（vanilla の `Item.Properties.craftRemainder`）②ツールチップに「容器：ガラス瓶（硫酸はガラスを溶かさない）」③重なる数は容器で決まる（瓶 16・フラスコ 1 など）
  - **機械**：中身入りを使ったら空の容器を「空き容器の出口」に出す（今の塩酸合成炉が空のバケツ・空のボンベを返すのと同じ）。中身を作る機械は空の容器を材料に取る（塩酸合成炉：水バケツ＋空のガラス瓶 → 塩酸の瓶）。共通の道具 `ConsumerBlockEntity.useContained(入口, 空き容器の出口)` を machine/ に
  - **相性表**（入れてはいけない組み合わせ）：フッ酸×ガラス（溶ける）、強アルカリの液×ガラス（長く置くと曇る＝⚠️ ゲームでは禁止にしない）、白リン×空気。GameTest で「全部の中身入りアイテムが、相性表で禁止の容器に入っていない」を毎回確かめる
  - **ミニ実験**（遊びの要素）：白リンの瓶を割る（地面に落として壊す）と、空気に触れて火がつく（壊れても戻せる小さな失敗）
- **今あるアイテムをどうするか**：**決定 Q28-3（DECISIONS）＝①**。案①全部いっしょに直す（硫酸・塩酸に瓶、白リンに水の瓶、水銀にフラスコ、二酸化硫黄を「袋」と書く。酸を作るレシピに空の瓶が要るようになる）／②作業台で使ったときに瓶が戻るだけ先に（作るときは今のまま＝瓶は「おまけ」）／③v0.3 の新しい物（フッ酸など）からだけ。仮の推し：①（v0.3 の最初、組立台より前）
- **作るファイル**：machine/Vessel（容器の種類と相性表）・content/Reg.contained・ConsumerBlockEntity の道具。容器のアイテムは材料の幹（ガラス瓶＝幹2 Chemistry、鉄のフラスコ・鉛の瓶＝幹1 Metallurgy、魔法瓶＝幹5 Vacuum）
- **GameTest**：中身入りを作業台で使うと空の容器が戻る／機械で使うと空き容器の出口に出る／相性表で禁止の組み合わせが1つもない／白リンが水の瓶に入っている
- **実装 IMP-33 で決めたこと（設計との違い）**
  - 重なる数は容器ごとに1つ：袋 64・ボンベ／瓶／フラスコ 16（設計の「フラスコ 1」は、水銀の機械が 1 つずつ入れる遊びと合わないので 16）
  - 機械で使ったときの空の容器は、出口スロットを足さず**機械の上に出す**（`Vessel.returnEmpty(level, pos, 使った物, 数)`。帯域精製炉・CZ 引き上げ機・拡散炉の白リン）。手で入れる機械は**プレイヤーに返す**（`Vessel.returnEmpty(player, pos, 使った物)`、シュプレンゲルポンプの水銀）。設計の `ConsumerBlockEntity.useContained` は作らなかった（電気を使わない機械もあるので machine/Vessel に置いた）
  - 中身を作る機械は空の容器を取る：塩酸合成炉に空のガラス瓶のスロット（6 番、前のセーブと番号を合わせて末尾）。瓶がないと塩酸は作らない（乾いた塩化水素ガスは袋なので要らない）
  - 水銀：辰砂の粉＋空の鉄のフラスコ＝「辰砂のレトルト仕込み」を作業台で作り、かまど・反射炉で焼くと水銀入りのフラスコ。電解槽の硫酸は減らない（電解質）ので瓶も戻らない
  - ツールチップの1行目に「容器：ガラス瓶」（TooltipText.lines の vesselKey、色は青）。画面の検査 tooltip_text もこの行を入れて測る

## 会社・仕組みの扱い ✅（2026-10-20 ユーザーの決定・全担当共通、INBOX S-002）

2. **歴史の事実だけ**：設立の年・最初に何をしたか・何を変えたかまで。今の株価・売上・時価総額・ランキングは書かない（すぐ古くなる・宣伝になる）
3. **国や会社をひいきしない**：いろいろな国・会社の例を並べる
4. **今まさに争われている話**（半導体をめぐる国どうしの対立・輸出の規制など）は、立場で見え方が違うので、へえ④で事実だけを中立に書くか、書かない

## 危ない技術の扱い ✅（2026-10-20 決定・全担当共通）
武器・爆発物・毒・事故は、技術の歴史と切り離せない。隠さずに学べるようにし、ゲームでは武器を作らない。
1. **歴史としては隠さない**：武器や戦争が技術を押し上げた事実（火薬と冶金、毒ガスと化学工業、レーダーと真空管、原爆と同位体分離、弾道計算と計算機など）は、ノードのつながりとして正直に書く
2. **ゲームでは武器を作らない**：バニラ以上の武器は足さない。火薬などは本物の平和な用途（花火・発破・推進）で遊ぶ
3. **具体的な作り方は書かない**：爆発物・銃・毒ガス・核兵器の具体的な配合・手順・寸法は、MOD にも公開データ（tech_network など）にも書かない。書くのは「何が・いつ・どう歴史を変えたか」まで
4. **被害も正直に**：へえ①（子ども）は「危ないもの」まで。へえ③④（大人・ガチ）で戦争の被害・事故の被害を書く
5. **ガス・薬品は工業の材料としてだけ**：機械の材料として使える。投げる・撒く・人や場所に向ける方法（投げられる瓶、ディスペンサーで撒く、矢に塗るなど）は作らない
6. **危険は「事故」として体験する**：危ない混ぜ方・換気のない漏れなどで、その場の機械が止まる・材料を失う・近くのプレイヤーに一時的な効果（吐き気・弱体化など）。地形は壊さず、狙った場所には起こせない（武器にならない）。例：今のガスホルダーの「爆鳴気でホルダーが空になる」
7. **アイテムの説明に本物の GHS の危険マーク（絵表示）と注意書き**（「可燃性」「急性毒性」「腐食性」など。国連の GHS の区分どおり、出典で確かめる）
8. **安全の技術もノードにする**（換気・防毒マスク・安全弁・ガス検知器・防爆・作業標準など。ノードを書くのはネットワーク担当）
9. **失敗の記録**：MOD の工程に関係する事故・公害（足尾銅山鉱毒・水俣病・イタイイタイ病・毒ガスなど）を、該当ノードのへえ③④と図鑑に「教訓」として載せる。出典で確かめ、被害者への配慮のある書き方にする（個人を晒さない、原因と社会の対応を中心に）

## 技術ネットワーク ✅（2026-10-20 決定・大きな方針）
### 考え方
- 技術は「ツリー（木）」ではなく「ネットワーク（網）」として扱う。合流（2つ以上の技術がそろって生まれる）・別ルート（A か B のどちらかで足りる）・古い技術が後の技術を生むつながりを大事にする
- 表に出る呼び名は「技術ネットワーク」。ファイル名（TECH_TREE.md など）とノード番号（[幹-番号]）はそのまま
- 各ノードに年（西暦。紀元前はマイナス）を項目として持たせる

### ウェブの「技術ネットワーク図」（先に作る）
- tools/gen_tree_views.py からノードと前提の JSON を書き出し、1枚の HTML で表示する
- 点の大きさ＝子孫の数（その技術から生まれた技術の多さ）、線の色＝前提との年の差
- 点を選ぶと「それが無いと作れなくなる技術」（子孫）を強調する

### ゲーム内の「技術ネットワーク画面」（構想）
- 専用画面にする（バニラの進捗画面は親が1つの木しか描けないため）。データはウェブ版と同じ JSON
- 霧の地図：作った技術は明るく、今作れる技術は光って脈打ち、その先は霧に隠れる
- ノードのカード：材料・作ると新しく見える技術の数・へえ①。カードはそのまま図鑑（へえ①〜④・確かさ◎○△・出典）
- 目的地ナビ：目的の技術をピン留めすると、足りない技術だけが光り「あと N 個」と出る
- 古い技術と新しい技術がつながった瞬間に通知する
- バニラの進捗（実績）は、章のゴールなど大きな節目だけに使う
- 追記（2026-10-20）：ゲーム内は**時間軸なしのネットワーク表示を基本にする**（年はカードに表示）。ウェブ版 network.html の「ネットワーク」表示と同じ考え方（つながりだけの力学レイアウト、ハブが中央）
- 追記（2026-10-20）：**見た目はバニラに溶け込むように**する。実績画面のタイル背景、インベントリの枠、マイクラのフォントとツールチップ、バニラの GUI の色を使う
  - ノードの枠はバニラの実績の3種類に合わせる：**技術＝四角**、**発見＝角丸**、**モノ＝トゲ付き**
  - 「つながった」通知は実績のトースト（右上に出る小さな札）の形で出す
  - バニラの絵はコピーしない（バニラのテクスチャを参照して使うか、自作する）。「公式」と誤認させる表記（Minecraft 公式・Mojang 製など）は使わない
- 検討：**モノを作ったとき、その裏にいる人たちの肖像が並ぶ演出**（画面の下を肖像が年代順に流れ、最後に「名前の残っていない、無数の人たち」のシルエット。ウェブの「人の壁」（network.html・node.html、NET-04）と同じ数え方・同じ肖像。モノを作った節目だけで、毎回は出さない。2026-10-20 提案 D-1）
- 検討：**遊んだ順番と人類の順番を比べる機能**（プレイヤーが技術を作った順番と、本物の年の順番を並べて見せる。「人類より先に〇〇を作った」など）

### 公開（tech-network）
- 技術ネットワークのデータ・参考文献・ネットワーク図は、のちに別リポジトリ tech-network に分けて公開し、世界中の人に監査してもらう
- データは「本物（history）」と「ゲーム（game）」の項目を分ける。ノードごとに JSON か YAML の1ファイル
- 自動チェック：存在しない前提を指していないか、出典なしの ◎ がないか
- 各ノードに「誤りを報告」→ GitHub Issue。ライセンスは CC BY 4.0 を候補

### 順番
①ノードに年 → ②ウェブのネットワーク図 → ③ tech-network として公開 → ④ゲーム内の画面

## 長期ビジョン（今の作業の優先順位は変えない）✅（2026-10-20）
- 人類が文明をどうやって組み立ててきたかの**設計図**を、どんな言葉の人でも、どんな時代の人でも、ゼロからでも読めるように残す（ロゼッタストーンやボイジャーのゴールデンレコードのように）
- 持たせたい性質
  1. **言葉を超えて読める**：つながり（線）・アイコン・肖像で意味が伝わる。説明は複数の言語で
  2. **ゼロから再建できる**：前提（何が先に要るか）・作り方・発見（どうやって分かったか）を、そろえて書く
  3. **残り続ける**：オープンなライセンス（CC BY 4.0 を候補）、単純な形式（JSON・テキスト）、テキスト版も用意する
- いつか作るもの：ネットワーク図の「読み方」のページ（記号・色・線の意味を、言葉に頼らず説明）、テキスト版の書き出し（図がなくても読める）
- これは方向の目印で、いまの実装の順番（v0.2b → 太陽電池 [B-12] …）は変えない

\## データモデル（アイテムが持つ情報）

\- material：element / purity(小数) / form(ore→metallurgical→polycrystal→single\_crystal) / dopant

\- ingot：material + diameter\_mm / defect\_density

\- wafer：diameter\_mm / dopant / surface(状態) / layers / min\_feature\_nm / overlay\_error\_nm / defects / flatness\_nm / mask\_id

\- photomask：design / min\_feature\_nm / durability

\- chip：design / node\_nm / grade(A/B/fail) / transistor\_count

\- v0.1 で使うのは material の element / purity / form だけ



\## 目玉：露光装置（第3章以降）

\- 解像度：CD = k1 × λ / NA

\- 焦点深度：DOF = k2 × λ / NA²（NAを上げるとピント範囲が狭くなる → CMPが必要）

\- 世代：コンタクト(g線436nm) → ステッパー(g線/i線365nm) → KrF 248nm → ArF 193nm → ArF液浸(NA〜1.35) → EUV 13.5nm(NA 0.33、真空＋鏡)

\## 26.x で変わった点（メモ）
- loot_table（26.3）: "conditions":[{"condition":…}] は廃止 → "condition": {"type":…} の単数（または述語ID文字列 "minecraft:tool/can_silk_touch"）。"functions":[{"function":…}] は廃止 → "modifier": [{"type":…}]。古い書式はエラーにならず**黙って無視**され、ログに WARN「validation problem … Unreachable entry!」が出るだけ（シルクタッチ無しでも鉱石ブロックが落ちていた。GameTest blockDrops で検出・修正）
- worldgen: configured_feature フォルダ/レジストリは feature に改名（26.1）。feature JSON は "config": {} の入れ子がなくなり、type と同じ階層に書く。targets の state は {"Name":…} ではなく文字列 "modid:block" で書く
- recipe / advancement / loot_table は単数形（1.21〜）
- items/ の client item 定義が必要（1.21.4〜）

- Fabric ItemTooltipCallback は引数4つ (stack, context, flag, lines)
- Screen.hasShiftDown() は廃止。Shift判定は Minecraft.getInstance().hasShiftDown()（Minecraft クラスのインスタンスメソッドに移動）

- Block の MapCodec / simpleCodec / codec() は廃止（26.x）。ブロッククラスに書かない

- I18n.exists() は廃止。翻訳キーの存在チェックは Language.getInstance().has(key)

- Player.displayClientMessage は廃止 → sendSystemMessage（引数1つ：Component。チャットに表示）
