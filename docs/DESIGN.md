\## 化学ルール ✅（2026-10-19 決定）
1. バニラの元素は使ってよい。ただし反応は本物どおり（石炭=C、骨粉=Ca3(PO4)2、砂=SiO2、硫黄ブロック=天然硫黄 など）
2. バニラにない元素は、本物の産出源を新しい鉱石として追加する。別の物で代用しない
3. 省略するのは「工程の細部（温度・触媒・段数）」だけ。「化学の筋道」は省略しない。省略箇所はガイドブックに明記
4. 全レシピに本物の反応式をつけて docs/CHEMISTRY.md で管理
5. 新しいバニラ要素をレシピに使う前に、ゲーム内で名前とIDを確認する

## 第1章 化学フロー（v0.1 改訂版）✅
- Ge入手A：閃亜鉛鉱（新鉱石・ワールド生成をv0.1に前倒し）→ 精錬 → 亜鉛 + Ge精鉱 + インジウム(少量)
  - v0.1は仮実装：かまど（→亜鉛）＋作業台で砕く（→Ge精鉱・インジウム少量）。第2章の機械共通化で専用の精錬炉に置換
- Ge入手B：石炭 →かまど→ 石炭灰 → Ge精鉱（産地限定の省略を明記）
- 硫黄：バニラは全てブロック（硫黄 sulfur／強力な硫黄 potent_sulfur／尖った硫黄 sulfur_spike）。「硫黄の破片」は存在しない。MODで「硫黄の粉」を追加：尖った硫黄1→粉2、硫黄ブロック1→粉4。尖った硫黄は硫黄の洞窟で素手でも回収可、行商人も販売。硫黄は可燃・爆発物（本物も火薬の成分）とガイドブックに明記
- 硫酸：硫黄の粉 →かまど（燃焼）→ 二酸化硫黄 SO2 →＋水バケツ→ 硫酸（接触法。SO2→SO3 の酸化・触媒V2O5 を省略と明記。専用機械ができたら3段に）
- 抽出：Ge精鉱 + 硫酸 → 二酸化ゲルマニウム GeO2 ／ GeO2 + 木炭 → 還元ゲルマニウム（未精製）（工業は水素還元と注記。純度の数字は精製炉の段階でのみ表示）
- 精製：帯域精製炉 98% → 6N → 9N（本物の GeCl4 蒸留の分を精製炉が担う、と明記）
- n型ドーパント：骨粉 + 砂 + 木炭 → リン（ヴェーラー法 Ca3(PO4)2 + SiO2 + C → P4。本物は約1500℃電気炉、温度は省略）
- p型ドーパント：インジウム（閃亜鉛鉱の副産物）
- ドーピング：帯域精製炉でゾーンレベリング（Pfann）。9N以上のGe（最大8）＋ドーパント1 → n型/p型Ge。作業台の固体混合は廃止
- 点接触型トランジスタ(1947)：n型Ge + 金塊2（針）+ 銅（ベース電極）
- 合金接合型トランジスタ(1952, PNP)：作業台で [In][n型Ge][In] → かまどで加熱（合金化）
- 成長接合型(1951, NPN)：第1章では解説のみ。第2章のCZ引き上げ機で実装
- トランジスタラジオ：合金接合型 ×3 + 鉄 + 銅 + レッドストーン
- 廃止：「石炭灰+水バケツ→粗Ge」「精製Ge+金+銅→トランジスタ」「粗Ge→精製Ge 仮レシピ」

## 第1章で学べること（順番そのものが学び）

## v0.2a 電気 設計 ✅（2026-10-19 決定）
- 単位：J（蓄積）/ W（消費）。1 W = 0.05 J/tick。本物の桁を使う（精製炉 数kW、アチsoン炉 MW級、EUV 約1MW）
- 電圧：データ欄（voltage）を用意。変圧器・高電圧は v0.4〜。電線損失は v0.2a は簡易（距離%）、式 I²R はガイドへ
- 他MOD互換：内部は J/W、共通エネルギーAPIへの換算ブリッジは後で
- 鎖：石炭→ボイラー→蒸気機関/タービン→発電機→電気。水車も（歴史順：水車→蒸気機関→タービン）
- 発電機：永久磁石式（磁鉄鉱）→ 自励式（1866 ジーメンス、鉄心のみ）のアップグレード
- 電解槽：水→H2+O2（黒鉛電極）。H2 で GeO2・WO3 を水素還元。木炭還元も残す（歴史的・小規模）
- 真空ポンプ→真空管（タングステンフィラメント）→高周波発振器 ＝ 仮①を置換
- アチソン炉（炭素+砂、大電力）→人造黒鉛→高純度ボート ＝ 仮②を置換
- 鉛蓄電池（方鉛鉱→鉛、硫酸）は v0.2a 後半 or v0.2b
- 容器：H2/O2 はボンベ（容器システムの第一歩）

### 鉱石の産状（本物→近似。地質構造がないため雰囲気の再現と明記）
- 磁鉄鉱：深層岩のみ（縞状鉄鉱層）＋ 浜辺の砂に「砂鉄」（漂砂鉱床・たたら製鉄）
- 鉄マンガン重石：花崗岩ブロック内のみ、少量（花崗岩縁の熱水石英脈）
- 方鉛鉱：閃亜鉛鉱と同じ高さ帯（Pb-Zn熱水鉱床）。将来、銀の副産物

## 技術ネットワーク ✅（2026-10-20 決定・大きな方針）
### 考え方
- 技術は「ツリー（木）」ではなく「ネットワーク（網）」として扱う。合流（2つ以上の技術がそろって生まれる）・別ルート（A か B のどちらかで足りる）・古い技術が後の技術を生むつながりを大事にする
- 表に出る呼び名は「技術ネットワーク」。ファイル名（TECH_TREE.md など）とノード番号（[幹-番号]）はそのまま
- 各ノードに年（西暦。紀元前はマイナス）を項目として持たせる

### ウェブの「技術ネットワーク図」（先に作る）
- tools/gen_tree_views.py からノードと前提の JSON を書き出し、1枚の HTML で表示する
- 点の大きさ＝子孫の数（その技術から生まれた技術の多さ）、線の色＝前提との年の差
- 点を選ぶと「それが無いと作れなくなる技術」（子孫）を強調する

### ゲーム内の「技術ネットワーク画面」（構想）
- 専用画面にする（バニラの進捗画面は親が1つの木しか描けないため）。データはウェブ版と同じ JSON
- 霧の地図：作った技術は明るく、今作れる技術は光って脈打ち、その先は霧に隠れる
- ノードのカード：材料・作ると新しく見える技術の数・へえ①。カードはそのまま図鑑（へえ①〜④・確かさ◎○△・出典）
- 目的地ナビ：目的の技術をピン留めすると、足りない技術だけが光り「あと N 個」と出る
- 古い技術と新しい技術がつながった瞬間に通知する
- バニラの進捗（実績）は、章のゴールなど大きな節目だけに使う
- 追記（2026-10-20）：ゲーム内は**時間軸なしのネットワーク表示を基本にする**（年はカードに表示）。ウェブ版 network.html の「ネットワーク」表示と同じ考え方（つながりだけの力学レイアウト、ハブが中央）
- 追記（2026-10-20）：**見た目はバニラに溶け込むように**する。実績画面のタイル背景、インベントリの枠、マイクラのフォントとツールチップ、バニラの GUI の色を使う
  - ノードの枠はバニラの実績の3種類に合わせる：**技術＝四角**、**発見＝角丸**、**モノ＝トゲ付き**
  - 「つながった」通知は実績のトースト（右上に出る小さな札）の形で出す
  - バニラの絵はコピーしない（バニラのテクスチャを参照して使うか、自作する）。「公式」と誤認させる表記（Minecraft 公式・Mojang 製など）は使わない
- 検討：**遊んだ順番と人類の順番を比べる機能**（プレイヤーが技術を作った順番と、本物の年の順番を並べて見せる。「人類より先に〇〇を作った」など）

\## データモデル（アイテムが持つ情報）

\- material：element / purity(小数) / form(ore→metallurgical→polycrystal→single\_crystal) / dopant

\- ingot：material + diameter\_mm / defect\_density

\- wafer：diameter\_mm / dopant / surface(状態) / layers / min\_feature\_nm / overlay\_error\_nm / defects / flatness\_nm / mask\_id

\- photomask：design / min\_feature\_nm / durability

\- chip：design / node\_nm / grade(A/B/fail) / transistor\_count

\- v0.1 で使うのは material の element / purity / form だけ



\## 目玉：露光装置（第3章以降）

\- 解像度：CD = k1 × λ / NA

\- 焦点深度：DOF = k2 × λ / NA²（NAを上げるとピント範囲が狭くなる → CMPが必要）

\- 世代：コンタクト(g線436nm) → ステッパー(g線/i線365nm) → KrF 248nm → ArF 193nm → ArF液浸(NA〜1.35) → EUV 13.5nm(NA 0.33、真空＋鏡)

\- 歩留まり：Y ≒ e^(−欠陥密度 × チップ面積)

\## 26.x で変わった点（メモ）
- loot_table（26.3）: "conditions":[{"condition":…}] は廃止 → "condition": {"type":…} の単数（または述語ID文字列 "minecraft:tool/can_silk_touch"）。"functions":[{"function":…}] は廃止 → "modifier": [{"type":…}]。古い書式はエラーにならず**黙って無視**され、ログに WARN「validation problem … Unreachable entry!」が出るだけ（シルクタッチ無しでも鉱石ブロックが落ちていた。GameTest blockDrops で検出・修正）
- worldgen: configured_feature フォルダ/レジストリは feature に改名（26.1）。feature JSON は "config": {} の入れ子がなくなり、type と同じ階層に書く。targets の state は {"Name":…} ではなく文字列 "modid:block" で書く
- recipe / advancement / loot_table は単数形（1.21〜）
- items/ の client item 定義が必要（1.21.4〜）

- Fabric ItemTooltipCallback は引数4つ (stack, context, flag, lines)
- Screen.hasShiftDown() は廃止。Shift判定は Minecraft.getInstance().hasShiftDown()（Minecraft クラスのインスタンスメソッドに移動）

- Block の MapCodec / simpleCodec / codec() は廃止（26.x）。ブロッククラスに書かない

- I18n.exists() は廃止。翻訳キーの存在チェックは Language.getInstance().has(key)

- Player.displayClientMessage は廃止 → sendSystemMessage（引数1つ：Component。チャットに表示）
